## 5. Build and checks in a cloud thread
1. Set up once: `python3 -m venv <env>` with Python 3.13, `pip install bpy==5.2.4 numpy pillow`. There is no Blender app. Clone the owner's asset library read only if a job needs it (`derekburnz/Roblox-Asset-Library`).
2. From `assets/clean-a-cat/blender/`: `<env>/bin/python build_all.py --render` builds and renders everything. It takes 25 to 45 minutes, so run it in the background and wait on a done file. `--only Cat_Muffin,Cat_Cotton` builds a few, `--no-fbx` skips the FBX copies. Do not edit a generator while a full build runs.
3. After a build, all four must be clean:
   - `grep "FAIL\|Traceback"` on the build log prints nothing.
   - line 3 of `assets/clean-a-cat/exports/gates.md` reads "N assets: N PASS ... 0 FAIL".
   - `python3 assets/clean-a-cat/blender/rbx_zfight.py | grep -v "zfight 0 area 0.000 glass 0"` prints nothing.
   - `python3 assets/clean-a-cat/blender/rbx_bowfit.py` ends "every bow clears the head piece and touches the head".
4. A build touches previews, sheets and FBX files it did not really change. Put those back before committing: `git status --short | awk '$1=="M"{print $2}' | grep "previews/\|\.fbx$\|sheet_" | xargs -r git checkout -q --`, then stage only what the job changed.
5. Every visible change gets a before and after sheet in `docs/concepts/clean-a-cat/` with a caption line in its `README.md`, and a copy in the shared folder for the owner.
6. Pull request with sections What, Check sheet, Counts, Honest limits and Test plan. Message Review-QA. Review-QA passes it and arms auto merge. Never sign off your own work.
7. Anything worn, see-through or touching another model needs Sync-Agent's look in Studio on dev after it merges.
8. Uploads of in-game pictures go to the group through the `upload-asset.yml` workflow once Review-QA has passed them; read the job log for the ids. Store icons and thumbnails are the owner's to upload.

## 6. Lessons from this thread
- **A Blender look is not a Roblox look.** A bow passed in Blender and cut into head pieces in Studio: loops are smooth and fuller in Roblox, the game wears a bow at 1.0 on a sitting cat built at 0.95, and a thin rod can sit whole inside a loop with no faces crossing. Measure on the Part models (`rbx_bowfit.py`) and say "seen only in Blender" until Sync has looked.
- **Say what was checked, not what is hoped.** A PR note called real cuts "light touches". Review-QA and Sync caught it. Write honest limits.
- **Small coat coloured pieces at the outline read as flaps at picture size.** Check every store picture at 150 px and every close crop for anything standing out past the cat's side.
- **Do not add an extra to a picture the owner did not ask for.** The bow added to thumbnail 3 was taken off within minutes. Change what was asked and offer the rest in words.
- **One function draws each face.** Cats: `cats.py` `_head`. People: one function in `townsfolk.py` draws customers and staff. HUD pictures have their own copy in `hud_icons.py`, and uploaded pictures do not change until they are rendered and uploaded again.
- **Names and counts are hooks.** Motion-FX and the game find parts by name (`_MudNN`, `_TangleNN`, `_FluffNN`, `BowSlot`, joints). Tell Motion-FX and Gameplay-Engineer before a rename, a count change or a pivot move.
- **Stay in the lane.** `SpaLayout.luau`, `CatRules.luau`, `VipRules.luau`, controllers and services are Gameplay-Engineer's; `src/client/UI/` is Design-Agent's; `Effects/` is Motion-FX's. Send a note with the numbers instead of editing.
- **Two old paw picture ids must never be wired.** Review-QA asked that they stay out of every file, so they are not written here either; use only ids listed in `HUD/Icons.luau` on main or on a closed upload issue.
- **Third party screenshots and the owner's reference pictures never go in a public repo.**
- **A thread can attach about 96 files in total.** After that, send new file paths to the coordinator to attach, or replace a file in place and attach its old path again.
- **Memory topic files stay under 4 KB.** Trim before adding.
